# Deploying EnvPlatform — Vercel (frontend) + Render (backend)

Architecture after deploy:

```
browser ──► https://<app>.vercel.app          (Vite/React build, static)
               │  /api/*  (vercel.json rewrite, same origin for the browser)
               ▼
            https://envplatform-api.onrender.com   (FastAPI in Docker, back/)
               │
               ▼
            MongoDB Atlas (free M0 cluster)
```

Because Vercel proxies `/api/*` to Render, the browser only ever talks to the Vercel
domain. That keeps the `httponly` refresh-token cookie first-party (`SameSite=lax`)
and avoids third-party-cookie blocking in Safari/Brave. CORS is therefore not on the
critical path, but we still allow-list the Vercel URL.

Files that make this work (already in the repo):

| File | Purpose |
|---|---|
| `render.yaml` | Render Blueprint: Docker web service from `back/`, health check `/health`, env vars |
| `back/Dockerfile` | Installs `libmagic1` (needed by `python-magic`), binds to Render's `$PORT` |
| `back/.dockerignore` | Keeps `venv/`, `archive/`, `uploads/`, tests out of the image |
| `front/env-platform/vercel.json` | SPA fallback to `index.html`, `/api/*` → Render rewrite, long cache for `/frames/*` |
| `front/env-platform/.env.example` | Documents `VITE_API_URL` (leave empty on Vercel) |

## 0. One-time prerequisites

1. **Push the branch** you want to deploy (currently `feature/back`) to GitHub.
   `render.yaml` has `branch: feature/back`; change it to `main` once you merge.
2. **MongoDB Atlas** (https://cloud.mongodb.com)
   1. Create a free **M0** cluster (pick a region close to Render's `singapore`, or change
      `region` in `render.yaml` — options: `oregon`, `ohio`, `virginia`, `frankfurt`, `singapore`).
   2. *Database Access* → add a user with read/write on `aqi_db`.
   3. *Network Access* → **Add IP → `0.0.0.0/0`** (Render free tier has no fixed outbound IP).
   4. *Connect → Drivers* → copy the URI and put the DB name in it:
      `mongodb+srv://USER:PASS@cluster0.xxxxx.mongodb.net/aqi_db?retryWrites=true&w=majority`
      URL-encode special characters in the password (`@` → `%40`, `#` → `%23`, …).
3. Accounts on https://render.com and https://vercel.com (sign in with GitHub).

## 1. Backend on Render

### 1.1 Create the service from the Blueprint

1. Render Dashboard → **New +** → **Blueprint**.
2. Connect the GitHub repo
   `Hrit66/Analysis-of-Cloud-Based-Environmental-Data-Integration-and-Management-System`.
3. Render finds `render.yaml` and shows one service **`envplatform-api`**.
   Keep the name `envplatform-api` — `vercel.json` points at
   `https://envplatform-api.onrender.com`. If Render says the name is taken, pick another
   and update the two `destination` URLs in `front/env-platform/vercel.json`.
4. It will ask for the `sync: false` values. Fill in:

   | Key | Value |
   |---|---|
   | `MONGO_URI` | the Atlas URI from step 0.2 |
   | `FRONTEND_URL` | `https://<your-app>.vercel.app` (you can put a placeholder now and fix it after step 2) |
   | `FRONTEND_ORIGINS` | same value; add more origins comma-separated (e.g. a custom domain) |
   | `SMTP_HOST`, `SMTP_USERNAME`, `SMTP_PASSWORD` | leave **empty** unless you have an SMTP account (Gmail app-password, Brevo, Resend SMTP…). Without SMTP, verification links are only stored in the `email_outbox` collection. |
   | `PLATFORM_ADMIN_EMAILS` | your e-mail, so your account gets platform-admin rights |

   `JWT_SECRET` is auto-generated by Render (`generateValue: true`) — do not reuse the dev one.
5. Click **Apply**. First build takes ~5–10 min (Prophet, scikit-learn, pandas are heavy).
   Watch *Logs*; success looks like `Uvicorn running on http://0.0.0.0:10000`.
6. Verify:
   * `https://envplatform-api.onrender.com/health` → `{"status":"healthy","database":"connected"}`
   * `https://envplatform-api.onrender.com/docs` → Swagger UI

   If `database` says `disconnected`, re-check the Atlas IP allow-list and the URI password encoding.

### 1.2 Things to know about the free tier

* The service **sleeps after 15 min idle**; the first request afterwards takes 30–60 s.
  The frontend's first login may feel slow — that is Render, not a bug. (Optional: ping
  `/health/ready` every 10 min with https://cron-job.org or https://uptimerobot.com.)
* **Disk is ephemeral**: anything written to `uploads/` or new `models/*.joblib` is lost on
  redeploy. The pre-trained models committed in `back/models/` are baked into the image, so
  forecasts/anomaly detection work. If you need persistent files later, add a Render Disk
  (paid) or push artefacts to S3/Cloudinary.
* 512 MB RAM. If logs show `Out of memory` during Prophet forecasts, upgrade to *Starter*.
* Free instances have **no Shell**. To bootstrap the first admin run it from your laptop
  against Atlas:
  ```bash
  cd back
  MONGO_URI='<atlas uri>' JWT_SECRET=x FIRST_ADMIN_EMAIL=you@example.com FIRST_ADMIN_PASSWORD='StrongPass123!' \
    python -m app.scripts.bootstrap_admin
  ```

### 1.3 Later changes

Every push to `feature/back` auto-deploys (`autoDeploy: true`). Env var edits in the
dashboard trigger a redeploy too. Changing `render.yaml` requires *Blueprint → Sync*.

## 2. Frontend on Vercel

1. Vercel → **Add New… → Project** → import the same GitHub repo.
2. **Root Directory** → click *Edit* → choose **`front/env-platform`**. (Required — the repo root has no `package.json`.)
3. Framework Preset: **Vite** (auto-detected from `vercel.json`). Build `npm run build`, output `dist`.
4. **Production Branch**: Settings → Git → set to `feature/back` (or merge to `main` first).
5. Environment Variables: **none needed.** Do *not* set `VITE_API_URL` — leaving it empty makes
   the app call `/api`, which `vercel.json` proxies to Render.
6. **Deploy**. Build takes ~1 min. You get `https://<project>.vercel.app`.
7. Go back to Render → `envplatform-api` → *Environment* → set `FRONTEND_URL` and
   `FRONTEND_ORIGINS` to that exact URL (no trailing slash) → Save (redeploys).

### 2.1 Verify end-to-end

1. Open `https://<project>.vercel.app` → landing page (dark scroll hero) loads.
2. `https://<project>.vercel.app/health` → should return the Render health JSON (proves the proxy works).
3. Sign up → if no SMTP, fetch the verification link from Atlas →
   *Browse Collections* → `aqi_db.email_outbox`.
4. Log in → dashboard at `/`. Refresh the page → still logged in (cookie refresh works).
5. Upload a CSV → analytics → export PDF.

### 2.2 Custom domain (optional)

Vercel → Settings → Domains → add `envplatform.yourdomain.com`, then add the same origin to
`FRONTEND_ORIGINS` on Render and set `FRONTEND_URL` to it.

## 3. Alternative: browser → Render directly (no Vercel proxy)

Only if you don't want the rewrite (e.g. you host the API on its own domain):

1. Vercel env: `VITE_API_URL=https://envplatform-api.onrender.com/api` (then redeploy).
2. Render env: `COOKIE_SAMESITE=none`, `COOKIE_SECURE=true`, `FRONTEND_ORIGINS=https://<project>.vercel.app`.
3. Remove the `/api/:path*` rewrite from `vercel.json`.

Drawback: Safari/Brave may block the cross-site refresh cookie, so sessions silently expire
after `ACCESS_TOKEN_EXPIRE_MINUTES`.

## 4. Troubleshooting

| Symptom | Fix |
|---|---|
| Vercel build: `No package.json` | Root Directory not set to `front/env-platform` |
| Vercel build: `Vite requires Node.js version 20.19+` | Settings → General → Node.js Version → 22.x |
| 404 on refresh of `/login` etc. | `vercel.json` rewrite missing — make sure the file is committed |
| `/api/...` returns 404/502 on Vercel | Render service name ≠ `envplatform-api`; fix the `destination` URLs |
| Login works, but logged out after 15 min | Cookie not being sent: ensure you are using the proxy (empty `VITE_API_URL`) or `COOKIE_SAMESITE=none` |
| CORS error in console | `FRONTEND_ORIGINS` on Render must exactly match the Vercel origin (scheme + host, no slash) |
| Render: `ImportError: failed to find libmagic` | You switched to the native Python runtime — keep `runtime: docker` |
| Render: build timeout / OOM during `pip install` | Retry once; otherwise upgrade the instance for the build |
| Render health `database: disconnected` | Atlas IP allow-list `0.0.0.0/0`, URI password URL-encoded, user has `readWrite` |
| First request takes 50 s | Free-tier cold start — see 1.2 |
